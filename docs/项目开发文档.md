## 1. 项目概述

### 1.1 项目简介

《行囊》是一款面向旅行爱好者的**个人旅行记忆与文案创作平台**。用户可以创建旅程、上传照片、记录日记、生成电子旅行手帐，同时AI可以根据照片场景与用户心情，生成富有质感的旅行文案。

### 1.2 核心价值

| 价值点           | 说明                                               |
| ---------------- | -------------------------------------------------- |
| **个人记忆存档** | 每次旅行的照片、文字、位置，被永久保存并结构化呈现 |
| **灵感表达辅助** | 面对美景说不出话时，AI帮你找到恰好的那句话         |
| **情感连接**     | 通过"灵感漂流"模块，感受陌生人在同一片风景下的共鸣 |
| **长期沉淀**     | 多年后可翻阅自己的"人生旅行地图"                   |

### 1.3 差异化优势

| 对比对象        | 《行囊》的不同                                   |
| --------------- | ------------------------------------------------ |
| 小红书/朋友圈   | 不止是分享，更是**为自己**的记录，有深度、有结构 |
| 传统旅行日记App | 多了**AI文案生成**和**灵感漂流**的社交温度       |
| Notion/笔记软件 | 专为旅行场景设计，开箱即用，视觉治愈             |

## 2. 目标用户与需求分析

### 2.1 用户画像

| 属性 | 描述                                                                           |
| ---- | ------------------------------------------------------------------------------ |
| 年龄 | 20-35岁                                                                        |
| 职业 | 学生、职场新人、自由职业者                                                     |
| 特征 | 热爱旅行、喜欢拍照、偶尔写点东西但不太满意                                     |
| 痛点 | 旅行照片躺在手机里吃灰；想发朋友圈但写不出文案；没有一个专门存放旅行记忆的地方 |

### 2.2 用户故事

```
作为一名旅行爱好者，
我希望每次旅行后能创建一个专属旅程，
上传照片并写下游记，
这样几年后我还能像翻书一样重温那段时光。

作为一名不太会写文案的人，
我希望上传一张风景照后，
AI能帮我生成几句适合发朋友圈的话，
这样我就不用对着照片发呆半小时了。

作为一个感性的人，
我希望偶尔能看到陌生人在同样的风景下写了什么，
这样我会觉得自己并不孤单。
```

### 3.3 模块二：此刻文案

#### 功能详情

| 功能       | 描述                                        | 优先级 |
| ---------- | ------------------------------------------- | ------ |
| 上传照片   | 从旅程中选择或新上传                        | P0     |
| 场景识别   | AI自动识别照片场景（海边/山巅/古镇/日落等） | P0     |
| 心情选择   | 平静/震撼/思念/释怀/期待/不舍/自由/治愈     | P0     |
| AI生成文案 | 生成3种风格：短句版/叙事版/诗意版           | P0     |
| 编辑文案   | 用户可手动修改AI生成的文案                  | P0     |
| 保存文案   | 保存到当前旅程的对应日期                    | P0     |
| 文案集     | 查看所有已保存的文案，可按心情/场景筛选     | P1     |
| 文案演变   | 记录用户对同一张照片多次生成的修改历史      | P2     |

#### 文案生成逻辑

```
MVP 阶段：
用户上传照片 + 选择心情
        ↓
AI识别照片场景（海边/山巅/古镇/日落/森林/城市...）
        ↓
构造Prompt：
  场景：{场景}
  心情：{心情}
  用户历史风格：{从用户历史文案中提取的关键词}
        ↓
调用 DeepSeek API 生成3种风格文案
  短句版（15字以内，适合社交媒体）
  叙事版（100-200字，适合日记）
  诗意版（像短诗，注重意象）

第二阶段增强（RAG）：
在 AI 识别场景后，增加一步：
  → 从知识库检索相似场景下的优质文案片段
  → 注入 Prompt 作为参考，提升文案质量
```

### 5.3 Redis Key 设计

```typescript
// 用户会话
USER_SESSION:{userId} -> JWT信息

// 热门文案排行
HOT_COPYWRITINGS -> ZSET (score=点赞数)

// 用户近期旅程
RECENT_JOURNEYS:{userId} -> LIST (最近5个)

// 文案生成缓存（防止重复生成）
COPYWRITING_CACHE:{photoId}:{mood} -> String (生成的文案)

// 限流
RATE_LIMIT:AI_GEN:{userId} -> 计数器 (每分钟限制次数)
```

## 8. AI能力实现方案

### 8.1 照片场景识别

**方案**：调用 DeepSeek 的多模态能力，上传照片直接识别场景。

**返回结果示例**：
```json
{
  "scene": "海边日落",
  "tags": ["海滩", "夕阳", "海浪", "橙红色"],
  "confidence": 0.95,
  "color_tone": "暖色调"
}
```

### 8.2 文案生成 Prompt 模板

```text
你是一位旅行作家，擅长用简洁而富有感染力的语言描述旅途中的风景与心情。

照片场景：{scene}
用户心情：{mood}
照片色调：{color_tone}

参考以下优质旅行文案的风格：
{reference_examples}

请根据以上信息，生成3种风格的文案：

1. 【短句版】15字以内，适合社交媒体配文，简洁有力，有画面感。
2. 【叙事版】100-200字，像一段日记，有细节、有感受、有故事感。
3. 【诗意版】50-80字，像一首短诗，注重意象和韵律，可以不完全押韵。

注意：
- 不要使用过于华丽的辞藻，保持真诚自然的语气
- 避免陈词滥调（如"岁月静好"、"诗和远方"）
- 如果用户的历史文案有特定风格，请尽量贴合
- 文案中不要出现"AI生成"、"根据您的需求"等字样
```

### 8.3 RAG知识库构建（第二阶段）

> 以下为第二阶段规划，MVP 阶段不实施。MVP 阶段直接调用 DeepSeek API + Prompt 模板生成文案。

**数据来源**：
- 经典游记书籍（《文化苦旅》《行者无疆》《旅行的艺术》）
- 优质旅行博主公开文章
- 诗歌中描写风景的片段（海子、顾城、木心）
- 电影台词中关于旅行/自由的句子

**处理流程**：
```
收集文本 → 清洗 → 切分（256字符+32重叠） → Embedding → 存入向量数据库（PgVector）
```

**检索逻辑**：
```
用户照片场景标签 + 心情 → 向量化 → PgVector 检索 Top-5
→ 取 Top-3 作为 Prompt 参考注入文案生成
```

### 10.2 Docker Compose 服务编排

```yaml
version: '3.8'
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: xingnang
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: root123
    ports:
      - "5432:5432"
    volumes:
      - pg_data:/var/lib/postgresql/data

  redis:
    image: redis:7.2-alpine
    ports:
      - "6379:6379"

  backend:
    build: ./backend
    ports:
      - "3000:3000"
    depends_on:
      - postgres
      - redis
    environment:
      DATABASE_URL: postgresql://postgres:root123@postgres:5432/xingnang
      REDIS_HOST: redis
      REDIS_PORT: 6379

  frontend:
    build: ./frontend
    ports:
      - "80:80"
    depends_on:
      - backend

volumes:
  pg_data:
```

### 10.3 CI/CD (GitHub Actions)

```yaml
name: Deploy to Aliyun

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Build and push Docker images
        run: |
          docker build -t xingnang-backend ./backend
          docker build -t xingnang-frontend ./frontend
          
      - name: Deploy to server
        uses: appleboy/ssh-action@v0.1.5
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_KEY }}
          script: |
            cd /app/xingnang
            docker-compose pull
            docker-compose up -d --build
```
