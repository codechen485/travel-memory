# 🗺️ 《行囊》开发行动指南

## 第一阶段：环境搭建与基础骨架（第1周）

> 目标：让项目能在本地跑起来，看到登录页面和空白旅程列表

### Day 1-2：项目初始化

**你要做的事**：

1. **创建项目目录结构**

```bash
mkdir xingnang
cd xingnang
mkdir backend frontend docs
```

2. **初始化后端（NestJS）**

```bash
npm i -g @nestjs/cli
nest new backend
# 选择 TypeScript
cd backend
```

3. **初始化前端（Vue 3）**

```bash
npm create vue@latest frontend
# 选择：TypeScript、Router、Pinia、ESLint
cd frontend
npm install
```

4. **安装后端额外依赖**

```bash
cd backend
npm install @nestjs/config @nestjs/jwt @nestjs/passport passport passport-jwt bcrypt class-validator class-transformer @prisma/client sharp
npm install -D prisma @types/passport-jwt @types/bcrypt
npx prisma init
```

5. **安装前端额外依赖**

```bash
cd frontend
npm install naive-ui @vicons/ionicons5 axios tailwindcss postcss autoprefixer
```

6. **配置 Tailwind CSS**

```bash
npx tailwindcss init -p
```

修改 `tailwind.config.js`，添加内容路径。

### Day 3-4：数据库与基础表

**你要做的事**：

1. **安装 Docker Desktop**（如果还没装）
2. **编写 docker-compose.yml**（启动 PostgreSQL 和 Redis）

```yaml
version: '3.8'
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: xingnang
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: root123
    ports:
      - '5432:5432'
    volumes:
      - pg_data:/var/lib/postgresql/data

  redis:
    image: redis:7.2-alpine
    ports:
      - '6379:6379'

volumes:
  pg_data:
```

3. **启动数据库**

```bash
docker-compose up -d
```

4. **配置后端 .env**

```env
DATABASE_URL=postgresql://postgres:root123@localhost:5432/xingnang
REDIS_HOST=localhost
REDIS_PORT=6379
JWT_SECRET=xingnangSecretKeyForJWTTokenGeneration123456789
JWT_EXPIRES_IN=7d
```

5. **编写 Prisma Schema**
   - 在 `prisma/schema.prisma` 中定义 User 模型
   - 字段：id, username, email, password, avatar, createdAt
   - 运行 `npx prisma migrate dev --name init`

### Day 5：用户注册登录

**你要做的事**：

1. **后端实现注册接口**
   - POST `/api/auth/register`
   - 接收 username, email, password
   - 密码用 BCrypt 加密
   - 返回成功消息

2. **后端实现登录接口**
   - POST `/api/auth/login`
   - 验证用户名密码
   - 返回 JWT token（先用简单实现，后续再完善）

3. **前端实现登录注册页面**
   - 两个表单页面：登录 / 注册
   - 调用后端接口
   - 成功后跳转到首页

### Day 6-7：旅程基础功能

**你要做的事**：

1. **后端创建 Journey 模型**
   - 在 Prisma Schema 中添加 Journey 模型
   - 字段：id, userId, title, coverImage, destinations(JSON), startDate, endDate, status, tags(JSON), createdAt

2. **后端实现旅程 CRUD 接口**
   - POST `/api/journeys` - 创建
   - GET `/api/journeys` - 列表（按 userId 查）
   - GET `/api/journeys/{id}` - 详情
   - PUT `/api/journeys/{id}` - 更新
   - DELETE `/api/journeys/{id}` - 删除

3. **前端实现旅程列表页**
   - 卡片网格布局
   - 显示封面图、标题、日期
   - 点击进入详情

4. **前端实现创建旅程弹窗/页面**
   - 表单：标题、目的地、日期范围、封面图上传（先不做图片上传，用默认图）

**第一周结束时你应该看到**：

- 项目在本地运行
- 可以注册登录
- 可以创建旅程
- 可以看到旅程列表

## 第二阶段：核心功能实现（第2-3周）

> 目标：完成日记、照片上传、文案生成三大核心功能

### 第2周：日记与照片

**Day 8-9：日记功能**

1. **后端创建 Diary 模型**
   - 在 Prisma Schema 中添加 Diary 模型
   - 字段：id, journeyId, date, title, content(富文本), mood, locationName, latitude, longitude, createdAt

2. **后端实现日记 CRUD**
   - 按旅程ID查所有日记（按日期排序）
   - 创建/更新/删除日记

3. **前端实现日记编辑器**
   - 使用富文本编辑器（推荐 wangEditor 或 TinyMCE，中文友好）
   - 日期选择器
   - 心情选择器（6个表情图标按钮）
   - 位置输入框（先手动输入，后续再加地图选点）

**Day 10-11：照片上传**

1. **后端实现照片上传接口**
   - POST `/api/photos/upload`
   - 接收文件，存储到本地 `uploads/` 目录
   - 用 sharp 生成缩略图
   - 返回访问 URL

2. **前端实现照片上传组件**
   - 拖拽上传区域
   - 上传进度条
   - 上传后显示缩略图

**Day 12-14：整合日记与照片**

1. **日记中关联照片**
   - 写日记时可以上传照片
   - 照片显示在日记下方

2. **时间线视图**
   - 按日期分组展示日记
   - 每个日记卡片显示：日期、标题、正文摘要、照片缩略图、心情图标

3. **旅程详情页完善**
   - 顶部：封面图 + 标题 + 日期范围 + 统计（照片数、日记数）
   - 下方：时间线列表

### 第3周：AI文案生成

**Day 15-16：接入 AI API**

1. **申请 DeepSeek API Key**
   - 去 platform.deepseek.com 注册，充值几块钱够测试用

2. **后端实现文案生成接口**
   - POST `/api/copywritings/generate`
   - 接收：照片URL、场景标签（先手动选）、心情
   - 调用 DeepSeek API 生成文案
   - 返回3种风格文案

3. **编写 Prompt 模板**
   - 参照文档第8章的 Prompt 模板
   - 先不加 RAG，直接用基础 Prompt

**Day 17-18：文案保存与管理**

1. **后端创建 Copywriting 模型**
   - 在 Prisma Schema 中添加 Copywriting 模型
   - 字段：id, userId, photoId, journeyId, sceneTag, mood, shortVersion, narrativeVersion, poeticVersion, finalVersion, isPublic, likesCount

2. **实现文案保存接口**
   - POST `/api/copywritings` - 保存
   - GET `/api/copywritings/my` - 我的文案列表

3. **前端实现文案生成页面**
   - 步骤1：上传/选择照片
   - 步骤2：选择心情（图标按钮）
   - 步骤3：点击生成，显示加载动画
   - 步骤4：展示3种风格文案，可切换查看
   - 步骤5：选择一种，编辑后保存

**Day 19-21：整合到旅程**

1. **旅程详情页增加文案入口**
   - 每篇日记旁边有个"生成文案"按钮
   - 点击后跳转到文案生成页，自动带入该日记的照片

2. **文案集页面**
   - 展示用户所有保存的文案
   - 可按旅程/心情/场景筛选

**第三周结束时你应该看到**：

- 可以在旅程中写日记、上传照片
- 可以对着一张照片生成AI文案
- 可以保存和管理文案

## 第三阶段：进阶功能（第4-5周）

> 目标：地图轨迹、文案质量优化、灵感漂流、电子手帐

### 第4周

**Day 22-23：地图轨迹**

1. **后端实现轨迹数据接口**
   - 从照片的 EXIF 中提取 GPS 信息
   - 按时间排序返回坐标数组

2. **前端集成 Leaflet 地图**
   - 在旅程详情页增加"地图"Tab
   - 绘制轨迹线
   - 在照片位置添加标记点
   - 点击标记点显示对应照片

**Day 24-25：文案生成质量优化**

1. **优化 Prompt 模板**
   - 根据用户反馈调整 Prompt
   - 增加更多场景和心情的组合

2. **收集优质文案语料**（为后续 RAG 做准备）
   - 收集 50-100 条优质旅行文案/诗句
   - 整理成结构化数据

**Day 26-28：灵感漂流**

1. **后端实现公开文案接口**
   - GET `/api/copywritings/public` - 分页查询公开文案
   - POST `/api/copywritings/{id}/like` - 点赞
   - POST `/api/copywritings/{id}/collect` - 收藏

2. **前端实现灵感漂流页面**
   - 场景分类 Tab（海边/山巅/古镇/日落/森林/城市）
   - 瀑布流卡片布局
   - 每张卡片：照片 + 文案 + 点赞数 + 收藏按钮

### 第5周

**Day 29-31：电子手帐**

1. **后端实现手帐生成接口**
   - 根据旅程ID，组装所有日记+照片数据
   - 生成 HTML 格式的手帐内容

2. **前端实现手帐翻页效果**
   - 使用 turn.js 或自研 CSS 翻页动画
   - 左页：照片，右页：日记+文案
   - 底部：页码 + 翻页按钮

**Day 32-33：旅程统计**

1. **后端实现统计接口**
   - 总天数、照片数、日记数、文案数
   - 去过哪些城市
   - 最常用的心情
   - 时间分布（按月/季度）

2. **前端实现统计展示**
   - 按需安装 ECharts 图表：柱状图（每月旅程数）、饼图（心情分布）、地图（去过的地方）

**Day 34-35：旅程封存**

1. **后端实现封存逻辑**
   - 封存后不可编辑
   - 封存时生成最终版手帐 PDF（可选）

2. **前端封存流程**
   - 封存确认弹窗
   - 封存后显示"已封存"标识
   - 提供分享链接
